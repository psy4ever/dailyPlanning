# 日有度｜发行路线与年度成本预算

核算日期：2026-10-22；目标是先给身边的人安装 Android APK，随后申请中国大陆 Android 应用市场。以下是规划预算，不是腾讯云账单或商店审核承诺。实际续费价、域名是否可注册和各渠道资料以结算页及申请页为准。

## 建议一次固定的技术选择

- 保留现有腾讯云上海轻量服务器和 MySQL；首批少量体验用户不预购第二台服务器、付费 WAF、短信、CDN 或额外数据库实例。先做真实负载、监控和备份，再按使用量扩容。
- 应用名和包名定为“日有度”与 `com.dayoudu.app`；主域名购买目标为 `dayoudu.com`。实际购买和发行签名密钥保管见[文档 21](21-名称域名与发行签名定案.md)。制作首个面向朋友的正式包之前，生成长期保管的**发行签名密钥**；将包名、签名证书指纹和版本规则存档。后续直发 APK 与目标商店如果需要互相覆盖升级，应核对渠道是否保留同一应用签名。[Android 签名说明](https://developer.android.com/studio/publish/app-signing)。目前的调试包不能假定可被新签名的正式包直接覆盖。
- 购买一个可备案的主域名；同一个主域名下的 `api.` 子域名无需再买一份。不用为了 HTTPS 单独购买付费证书。域名、备案和 Caddy 步骤见[文档 19](19-域名HTTPS与公网安全上线.md)。
- 首次分发用**签名 APK 文件**给受邀者；完成真实云端、备份、安全与隐私验收后，申请选定的应用市场。Google [Android 官方文档](https://developer.android.com/distribute/marketing-tools/alternative-distribution)确认可通过文件或网站直接分发 APK；接收者需允许该来源安装，更新需要自行管理。直接分发不豁免在中国大陆对外提供联网 App 的适用备案与隐私要求。

**规划数：**按当前服务器购买页的 90–100 元/月粗估，单服务器 + 一个普通域名 + 小额异机备份预留，约 **1200–1530 元/年**。为续费价变化、少量流量和备份留出余量，可先把首年现金预算上限定为 **2000 元**；这是项目内部控制线，**不是固定报价或支出承诺**。超出预算前先核对账单并重新决策。尚未包括人工开发时间、第三方代理、商标注册、付费营销、短信/邮件服务、交易抽成以及后续扩容。

## 不等域名的本地体验 APK

仅使用手机本地 Room/SQLite 的体验包可以先交给熟人安装：计划、记账、饮食分别保存在每台手机上，不要求注册、域名或服务器连接。此阶段没有跨设备同步；卸载或换机会丢失未导出的记录，应先在“我的”导出备份 JSON。当前 Debug APK 可用于少量熟人验证，但云端登录按钮在对方手机上不可用，也不能把 Debug 签名当作长期发行签名。正式可持续更新的离线发行包仍需先固定发行密钥、包名、版本号并做真机验收。

## 联网 APK 与正式上架的前置条件

1. 公网 HTTPS 与备案、修复反代后的登录限流、限制公开注册滥用；SSH 密钥与主机安全更新。
2. 计划、记账、饮食在**个人正式服务器**完成真实写入、离线再同步、另一台设备读取；验证账户隔离和恢复。
3. 自动加密备份、服务器外副本、隔离环境恢复演练、证书/API/备份告警。
4. 固定签名密钥、包名和版本号；发布版不使用调试地址；先解决已有调试安装的数据迁移，再把签名 APK 给朋友安装。
5. 给外部用户清楚的隐私说明、账户删除和数据处理流程；选择商店后按其最新规则准备图标、截图、应用介绍、备案号、开发者身份及其他必要材料。

**阶段门槛：**仅本地存储的少量熟人体验可先开展；接入中国大陆服务器并对外提供联网服务前完成相应备案、公网安全和 1–4 的云端验收；完成 1–5 并通过目标渠道审核后再公开上架。发行文件能先做出来，但不能把当前调试 APK 当成已经可长期更新的成品。
