## 文档格式 v1

`DailyPlanDocument` 是可持久化的 JSON 日计划格式，也可由未来 AI、文件导入或“复用一天”生成。`schemaVersion=1`；`date` 为源日元数据，`timezone` 为 IANA 时区；每项包含 `title`, `startMinute`（相对源日 00:00）, `durationMinutes`（必须于当天结束）, `fixed`, `reminderMinutesBefore?`, `reminderSilent`。文档不包含计划 ID、执行状态、实际时长、评分、现金；导入到目标日时生成新的 ID。用户在导入预览确认前不写库。Room 中的 `plans` 仍是执行态的唯一可编辑存储，文档是批量输入/导出契约，避免双写 JSON 与计划行后出现不一致。

## 改动边界

改 `TodayScreen.kt`、`PlanningRepository.kt`、`PlanningEntities.kt`，新增 `data/DailyPlanDocument.kt`：仓库导出、导入和未来 AI 草稿共同引用；不新增 UI 公共包装层。为软移除升级 `NutritionDatabase.kt` / `BackupRepository.kt`，`ReminderScheduler.kt` 避免已移除计划发出提醒。修改需求、架构、接口设计文档与独立指令记录。不改饮食、洞察算法或其他主页面。

## 反向验收

| 检查项 | 结果 |
|---|---|
| 页面结构与交互 | 空日显示新建焦点卡；首项出现后焦点卡隐藏，时间线成为主体；`+ 计划`用于追加第二项；卡片主体打开详情，快捷操作只保留完成；模拟器已走通 |
| 日期与时间 | 新建/调整使用 Android 日期选择器接时间选择器，跨日可选；模拟器确认两个原生选择器依次出现并保存成功 |
| 执行记录 | 关联计划的片段在详情内显示；详情可开始或补记关联执行；未关联活动从“其他活动”进入详情；计划完成不生成虚构时长 |
| 取消与移除 | 取消仍保留时间线状态；移除二次确认、软隐藏并停用提醒，支持当前页面撤销；模拟器验证移除/撤销 |
| 文档路径 | 导出真实日计划为 v1 JSON，导入文件或复用前一天均先预览再走 `applyDayDocument` 事务写入；模拟器查看 JSON 内容并分别走通导入/复用 |
| 数据/接口 | 新增 Room v8→v9 无损迁移与 `deletedAtMillis`；备份 v9 兼容导入 v8；HTTP 与 AI 尚未接入，设计字段不冒充已实现接口 |
| 负载/范围 | 今天页仅观察所选日期计划、活动和当前计时；文档只在点击导出/复用/导入时构造或读取；其他主页面与算法未动 |
| 验证 | `:app:assembleDebug`、`:app:lintDebug` 成功，Lint 剩余为已有依赖/图标/风格提醒；模拟器安装运行、截图与交互验证成功 |

与概念原型的差异：空数据没有示例任务；实际执行时长只在真实记录存在时显示；整天导入采用“追加”，不静默替换。待确认：未来 AI 提案的来源标识、冲突重排策略、服务端 OpenAPI；重复系列与多日模板管理仍未实现。新增文件仅 `data/DailyPlanDocument.kt`、Room 9 schema JSON 与本映射文档；`DailyPlanDocument.kt` 被 Repository 和 Today UI 引用，schema JSON 用于数据库迁移追踪。
