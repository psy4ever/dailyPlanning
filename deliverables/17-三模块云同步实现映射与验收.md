# 三模块云同步实现映射与验收

日期：2026-10-21。需求依据为[三模块接入范围](16-三模块云端接入范围与验收.md)、现有 Room v10 和本地 Repository。计划、记账、饮食统一交付。本文件描述本轮实际代码；早期接口提案的路径不视为已实现。

## 实现映射

| 用户操作 / 数据 | 实现 |
|---|---|
| 注册与登录个人云账户 | 首次启动从服务器环境保留初始账户；App 注册只填可重复昵称和 8–16 位密码，服务器在数据库事务中自动发放 `00000001`–`99999999` 的八位 UID 并自动登录。Spring Security Bearer 会话；密码 BCrypt，令牌仅以 SHA-256 保存到数据库，30 天有效 |
| 计划新增、改期、完成、取消、删除/恢复及批量生成 | 既有 `PlanningRepository` 保存 Room；数据库触发器同事务标记计划，上传包含计划与改期历史的完整记录组 |
| 活动开始、暂停、继续、结束、补记及现金/标签修改 | 上传活动、全部计时片段与标签；分类及项目先同步，计划关联保留；不自动生成独立账目 |
| 账目新增、修改、删除 | 同步 `ledger_entries` 完整行；金额保持十进制字符串、保留时区、版本和删除标记 |
| 食物维护 | 同步全部 `food_versions`，旧版本只读；新版本追加，历史餐食快照保持 |
| 三餐/加餐及摄入编辑、删除/恢复 | 摄入与明细在一个操作中提交；保留食用量、空值语义及营养快照 |
| 离线、失败重试 | Room 事务触发器 + 持久化脏记录、不可变请求、WorkManager 网络条件与指数退避 |
| 其他设备拉取 | 服务端按账户串行分配变更序号，追加变更快照，分页读取；本地事务应用后再推进游标 |
| 同时编辑 | 版本不符返回 409；“我的 → 云端同步”可预览双方内容并确认保留版本；不静默覆盖 |
| 同名分类/项目 | 云端返回已有记录；选择保留云端后，本地合并 ID 并重排关联活动的同步任务 |
| 数据恢复 | 逻辑备份、加密及 HMAC 验证；提供隔离 Docker 数据库恢复、关联校验、认证和业务接口读取脚本 |

客户端代码：`CloudStore.kt`、`CloudSync.kt`、`CloudPanel.kt`；服务端代码位于 `server/src/main/java/com/dayoudu/cloud/`。页面已有业务写入入口通过 SQLite 触发器统一接入，不需要每个按钮重复调用网络。

## 实际数据契约

两端持有相同的 `sync-contract.json`，由现有 Room v10 字段生成，覆盖 7 类记录组和 11 张本地业务表：

| kind | 记录组 |
|---|---|
| `category` | `time_categories` |
| `project` | `projects` |
| `plan` | `plans` + `plan_revisions` |
| `activity` | `activities` + `activity_segments` + `activity_tags` |
| `ledger` | `ledger_entries` |
| `food` | 一个 foodId 的全部 `food_versions` |
| `intake` | `intakes` + `intake_items` |

这里使用统一同步 API 承载三个业务模块。云端实际建表为 `cloud_accounts`、`cloud_sessions`、`cloud_records`、`cloud_changes`、`cloud_operations`，由 Flyway V1 迁移建立。V2 引入 `uid` 和可重复的 `account_name`；V3 将旧账户发给数字 UID，原登录名保存在 `legacy_uid` 供过渡期登录，新增 `cloud_uid_sequence` 单行发号表。若正式库当前只有 `yuan` 一个账户，升级后它获得 `00000001`；账户内部 owner ID、密码哈希和业务记录不变。完整记录组作为经过字段和业务校验的 JSON 文本存入 MySQL `LONGTEXT`，ID、账户归属、版本及变更顺序为独立 SQL 列；当前没有声称另外建立 11 张同名云端业务表。这样能原子保留多表记录组和历史快照；未来复杂报表可新增关系表/投影迁移。

实际接口：

| 路径 | 用途 |
|---|---|
| `GET /health` | 完成启动初始化后检查数据库连接 |
| `POST /api/v1/auth/register` | `{accountName,password}` 创建账户；数据库锁定发号表、分配 UID、写入账户和会话，在同一事务提交；响应与登录相同，字段无效返回 422，号段耗尽返回 409 |
| `POST /api/v1/auth/login` | `{uid,password}` → `{token,ownerId,uid,accountName,expiresAtMillis}`；旧 `yuan` 等登录名过渡期仍可使用，响应返回新数字 UID |
| `POST /api/v1/auth/logout` | 撤销当前 Bearer 会话 |
| `GET /api/v1/account/me` | 认证后读取 UID 和账户名 |
| `POST /api/v1/account/name` | 认证后修改可重复的账户名；UID 不变 |
| `GET /api/v1/sync/contract` | 认证后检查字段契约 |
| `POST /api/v1/sync/operations` | 写入某一类记录组 |
| `GET /api/v1/sync/changes?cursor=0&limit=5` | 按账户增量拉取，返回 `items,nextCursor,hasMore`；limit 最大 20 |
| `GET /api/v1/records/{kind}/{id}` | 认证后查询当前记录组 |

写入字段固定为 `operationId,kind,id,expectedVersion,payload`，其中 `payload={tables:{表名:[完整字段行]}}`。响应含 `kind,id,serverVersion,payload,seq`；冲突为 HTTP 409 和 `details` 中的云端记录，字段校验为 422。客户端不传可授权的 ownerId；服务端从 Bearer 会话确定账户。

契约保留实际 Room 字段名及 Unix 毫秒，十进制仍为字符串、SQLite 布尔仍为 0/1；与早期 v0.2 提案的 ISO 时间和分资源 URL 不同，以本文件和实际契约为准。单个操作序列化后最大 1 MB，HTTP POST 最大 2 MB；批量计划会分成独立计划记录组逐项上传，同一计划的历史与同一活动的片段保持原子性。

## 同步与本地升级

- 业务 Room 仍为 v10，既有 v1→v10 迁移不变。`onOpen` 安装独立版本号为 1 的辅助 SQLite 表与触发器：`cloud_meta`、`cloud_dirty`、`cloud_outbox`、`cloud_versions`、`cloud_conflicts`。旧数据不会因接入而清库。
- “我的”只显示一张个人资料卡：未登录时可编辑本机昵称、登录或创建账户；注册只填写昵称和密码，成功后展示服务器分配的 UID 供保存。登录后同一昵称显示于本机和云端，并展示 UID、同步与退出操作。服务地址由应用配置，不在登录页输入。现有三模块记录在首次绑定时标记为待上传；可在“我的 → 备份与恢复”单独导出备份。本机数据绑定一个云端账户，避免不同账户数据混合；已绑定的安装会在发起新账户注册前阻止切换，同一已认证账户可以从隧道地址切换到正式 HTTPS。
- 脏记录与业务变更同事务提交。准备上传时冻结 request 和 operationId；网络超时按原请求重试，确认后只清理相同本地修订。上传过程中再次编辑会保留为下一次请求。
- 服务端按账户行锁串行处理幂等检查、版本校验、业务保存及变更号分配，确保变更游标与事务提交顺序一致。
- 应用云端快照时抑制再次入队，游标与本地应用在同一事务提交。活动与本机睡眠/实际活动重叠时保留冲突，不覆盖本机记录；拉取计划后重新调度本机提醒。
- 页面中即时变更触发同步；周期任务最短 15 分钟。无网络保留队列，恢复网络或手动同步后重试。
- Android 会话令牌用 Android Keystore 的 AES-GCM 加密保存，密码不持久保存。Debug 自动选择模拟器的 `10.0.2.2` 或 USB 真机反向端口的 `127.0.0.1`；Release 在构建时配置 HTTPS 服务域名，登录界面不要求用户填写地址。

## 已执行验证

独立本地 MySQL 8.4.11 测试库，不连接用户云数据库：

- 后端 H2 14 项测试通过：数字 UID 发号连续性、原登录名兼容、注册会话与可重复昵称、认证失败、账户隔离、精确金额、重复操作、并发同版本冲突、无效写入回滚、同名分类合并、计划与计时片段、食物历史及摄入快照、删除及变更游标、未知引用拒绝（部分场景在同一测试内）。V3 迁移另在独立 MySQL 8.4.11 测试库通过：旧 `yuan` 得到 `00000001`，owner ID、原昵称、密码哈希和账目记录归属不变。未对用户云端数据库执行迁移。
- 数字 UID 改动后模拟器 10 项测试通过：从独立 H2 服务注册取得八位数字 UID，用该 UID 登录，再完成计划、记账、饮食 HTTP 往返与空白数据库恢复；其余包括本地事务、冲突与 Keystore 检查。设备执行返回 `Finished 10 tests`、`BUILD SUCCESSFUL`；测试未写入服务器正式数据。
- 实际链路为“模拟器 Room → HTTP → Spring Boot → MySQL 8.4.11 → 另一份空 Room”。验证中文/单引号、金额、活动暂停/继续产生的两个片段、改期历史、食物历史版本、摄入营养快照及软删除。
- 独立 MySQL 逻辑备份恢复到另一个本地数据库，启动打包后的服务器，38 条测试记录组通过关联/业务校验，认证后增量业务接口可读取。
- Android 新版 Debug APK 构建通过；此前 Lint 0 errors（现有及样式建议警告保留）。创建账户弹窗现在只包含昵称、密码，无网址或手填 UID；登录页输入 UID 和密码。
- 备份脚本通过语法与 HMAC 篡改拒绝检查；Compose YAML 可解析，检查确认 MySQL 不发布端口、API 仅绑定 127.0.0.1。

复现入口为[部署与操作步骤](18-云端部署与手机联调操作.md)。测试只写随机命名设备库和独立本地 MySQL，未向正式生活数据写入示例；本机档案仍由既有应用逻辑维护。

## 当前限制与待云端验收

- 用户服务器上次反馈运行 `daily-rhythm-api:0.2.1`：db 与 api 均为 `healthy`，回环地址 `/health` 返回 `{"status":"ok"}`。本轮数字 UID 版本 `0.2.3` 尚需上传和启动；旧服务没有此发号接口。尚未验证三个模块从个人 App 写入该服务器及从另一设备拉取。
