`GET /record-modules` 只提供入口元数据，不预取饮水或周期详情。详情进入模块时才调用；食物列表只在食物选择器打开时搜索。保存一条摄入后，更新本地单条记录与当天营养汇总缓存；若洞察页面正在显示同一天，标记对应读模型失效并在可见时刷新。其他日期的洞察不需要重新请求。

## 3. 代码实现前检查点

1. 先确定设计数据来自本地 Repository 还是已实现的服务端接口。未实现 HTTP 时显示本地空状态，不伪造真实响应。
2. 对每个展示字段核实名称、单位、可空性、枚举和版本；意义相近但无法证明相同的字段标 `字段未确认`，不自动绑定。
3. 明确触发操作、变化实体、要失效的读模型和复用条件；进入“今天”时不预取营养/周期，进入“洞察”时不重复抓整天餐食明细。
4. 代码落地后反向检查原型、接口与实现；更新本表的“当前代码位置”和状态。当前“已确认实现”：**无**；“接口暂不支持”：全部设计接口尚未实现；“与原型存在差异”：交互预览以真实可检视的条形结构表达视觉方向，部分内容比静态概念图简化；“TODO”：实际 DTO/实体/组件定位、饮水/周期字段与权限细则。
