## 1. 找到实例

进入[轻量服务器控制台](https://console.cloud.tencent.com/lighthouse/instance/index)，选择购买时的地域，找到实例。

记录：实例名称、实例 ID、地域、运行状态、操作系统、CPU / 内存、系统盘、购买时长和到期日。确认状态为“运行中”。这些值以实际实例为准，不把之前套餐页的推荐值当作已购配置。

## 2. 在网页终端登录

点击实例的“登录”，优先使用页面提供的“免密登录 / 自动化助手”方式进入 OrcaTerm 网页终端。无需先在电脑安装远程终端客户端。登录后一般能看到以 `$` 或 `#` 结尾的命令提示符。

如果登录失败，保留错误信息，按实际错误检查实例运行状态和连接方式；先不批量开放端口或重置系统。

## 3. 执行只读检查

以下命令在云服务器网页终端执行，每行一条：

```bash
whoami
cat /etc/os-release
uname -m
nproc
free -h
df -h /
```

核对目标：

| 命令 | 核对内容 |
|---|---|
| `whoami` | 当前登录用户，后续据此确定是否使用 sudo |
| `cat /etc/os-release` | 实际系统和版本，目标为 Ubuntu 24.04 LTS |
| `uname -m` | 机器架构，目标为 x86_64 |
| `nproc` | 可用 CPU 核数 |
| `free -h` | 内存，目标至少约 4 GB；显示值会受单位和系统预留影响 |
| `df -h /` | 根文件系统大小及剩余空间；文件系统显示值可能略小于系统盘标称容量 |

把以上输出用于下一步安装方案。当前不需要提供密码、验证码、访问密钥或私钥。

## 5. 已确认系统后的 Docker 安装

本次采用 Ubuntu 软件源提供的 `docker.io` 和 `docker-compose-v2`。这与前述“Docker 官方 apt 源”的候选方案有所调整，实际执行以本节为准。使用发行版软件源便于当前网页终端逐条执行；记录实际包版本后，再固定后续部署依赖和镜像版本。

以下命令在服务器终端逐条执行，上一条成功后再执行下一条：

```bash
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo docker --version
sudo docker compose version
sudo systemctl is-active docker
```

预期：Docker / Compose 输出版本，最后一条返回 `active`。如出现 apt 下载失败、找不到软件包或其他错误，先保留错误输出，按实际问题处理。

通过后记录包版本：

```bash
dpkg-query -W -f='${Package}=${Version}\n' docker.io docker-compose-v2
```

相同安装过程已整理为仓库脚本 [`deploy/bootstrap-ubuntu.sh`](../deploy/bootstrap-ubuntu.sh)，供后续上传或克隆仓库后复用。用户终端截图已确认手工执行安装成功：Docker 29.1.3（build `29.1.3-0ubuntu3~24.04.2`）、Compose 2.40.3（build `2.40.3+ds1-0ubuntu1~24.04.1`），Docker 服务返回 `active`。该脚本本身尚未在服务器运行。后续做完整可复现部署时，需归档实际 apt 包版本和可用安装来源。

官方依据：[Ubuntu Docker 管理指南](https://ubuntu.com/server/docs/how-to/containers/docker-for-system-admins/)、[Ubuntu 24.04 Compose v2 软件包](https://packages.ubuntu.com/eu/noble/docker-compose-v2)。

## 6. MySQL 镜像拉取与版本记录

Docker 服务已通过检查后，先确认镜像仓库能否访问，在服务器终端执行：

```bash
sudo docker pull mysql:8.4
```

本步骤仅下载官方 MySQL 8.4 系列镜像，不创建数据库实例。成功后记录最后输出中的 `Digest: sha256:...`；后续 Compose 使用相应 digest 固定镜像，避免仅依赖可移动的版本标签。

若拉取超时、连接失败或出现访问限制，先记录完整报错再选择经过验证的镜像分发路径；当前没有配置公共加速地址。只有拉取成功后才进入数据库密码、持久卷、内部网络和健康检查的配置。

首次拉取时，用户截图显示 Docker Hub 的 `registry-1.docker.io:443` 连接出现 `i/o timeout`。配置腾讯云镜像源后，用户已反馈拉取成功，最终结果见本节末尾。

官方依据：[MySQL 官方镜像](https://hub.docker.com/_/mysql)、[Docker 拉取与 digest 固定](https://docs.docker.com/reference/cli/docker/image/pull/)。

### Docker Hub 超时后的检查

腾讯云[轻量服务器镜像加速说明](https://cloud.tencent.cn/document/product/1207/45596)提供 `https://mirror.ccs.tencentyun.com`，明确仅支持内网访问。在当前服务器执行：

```bash
curl -I --connect-timeout 10 --max-time 20 https://mirror.ccs.tencentyun.com/v2/
sudo docker info --format '{{json .RegistryConfig.Mirrors}}'
```

第一条用于确认该实例到镜像入口的网络和 TLS 可达性，第二条只显示当前配置的镜像加速地址。HTTP 200 或 registry 返回的 401 可表明已连通服务入口，但不代表已经可以成功拉取指定 MySQL 镜像。镜像入口可达后，再备份并合并修改 `/etc/docker/daemon.json`，保留现有设置，校验配置再重启 Docker。当前尚未修改该服务器配置或验证加速拉取。

最新结果：用户截图确认腾讯云镜像入口返回 `HTTP/2 200`，Docker 当前 mirrors 列表为 `[]`。下一步采用腾讯云官方内网镜像源。

### 合并镜像源配置、校验并重试

可复用的本地脚本为 [`deploy/configure-docker-mirror.py`](../deploy/configure-docker-mirror.py)。脚本备份原有文件并保留其他设置，去重合并镜像地址；已在本地临时配置文件检查创建、备份、选项保留、重复执行与非法 JSON 处理。云服务器端仍待用户执行。

以下多行命令需要在支持粘贴的 SSH / OrcaTerm Shell 终端执行，包括最后一行 `PY`。用户此前采用的 VNC 终端不支持常规复制粘贴；现已按第 7 节登录本地 SSH，可在已连接的云服务器命令行中执行此段：

```bash
sudo python3 - <<'PY'
import json, pathlib, shutil, time
p = pathlib.Path('/etc/docker/daemon.json')
d = json.loads(p.read_text()) if p.exists() else {}
assert isinstance(d, dict), 'Configuration must be a JSON object'
mirrors = d.get('registry-mirrors', [])
assert isinstance(mirrors, list) and all(isinstance(x, str) for x in mirrors)
if p.exists():
    backup = str(p) + '.bak-' + str(time.time_ns())
    shutil.copy2(p, backup)
    print('Backup:', backup)
d['registry-mirrors'] = list(dict.fromkeys(['https://mirror.ccs.tencentyun.com'] + mirrors))
p.parent.mkdir(parents=True, exist_ok=True)
p.write_text(json.dumps(d, indent=2) + '\n')
print('Docker mirror configuration saved.')
PY
```

然后校验配置：

```bash
sudo dockerd --validate --config-file /etc/docker/daemon.json
```

仅当返回 `configuration OK` 后，逐条执行：

```bash
sudo systemctl restart docker
sudo docker info --format '{{json .RegistryConfig.Mirrors}}'
sudo docker pull mysql:8.4
```

记录镜像源列表以及最终拉取状态和 digest。若校验或重启报错，保留输出，先不继续拉取；备份位置见第一段命令输出。配置校验方式见 [dockerd 官方说明](https://docs.docker.com/reference/cli/dockerd/)。

## 7. 从 VNC 切换到 Windows SSH，支持粘贴命令

用户此前通过 VNC 登录；腾讯云[官方说明](https://intl.cloud.tencent.com/zh/document/product/1103/41526?lang=zh)指出 VNC 不支持复制粘贴。因此第 6 节多行 Python 配置命令应在支持粘贴的终端执行。

1. 保留 VNC 窗口，在服务器手动输入以下只读命令，显示服务器的 ED25519 主机公钥指纹：

   ```bash
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```

2. 在本人 Windows 电脑上打开“终端 / PowerShell”，执行（将地址替换为实例公网 IP）：

   ```powershell
   ssh ubuntu@<服务器公网IP>
   ```

3. 首次连接时，将 SSH 显示的 ED25519 `SHA256:...` 与 VNC 中的指纹比较，一致后输入 `yes`。输入该服务器 `ubuntu` 账户密码（与 VNC 登录相同，输入时无字符回显）。不在聊天中提供密码或私钥。
4. 成功后会看到远程 `ubuntu@...:~$` 提示符，此时可在 Windows Terminal 用 `Ctrl+Shift+V` 或右键粘贴命令。第 6 节的脚本可整块粘贴，配置校验与重启步骤仍按顺序执行。

若连接超时，按实际实例防火墙和 SSH 服务状态排查 22 端口访问；若身份验证失败，按实际 SSH 登录策略排查。

最新结果：用户已在本人电脑通过 SSH 登录并反馈 Ubuntu 欢迎信息。系统为 Ubuntu 24.04.4 LTS、x86_64，内核 6.8.0-138-generic；根文件系统显示约 98.31 GB。服务器软件升级提示尚未执行。
