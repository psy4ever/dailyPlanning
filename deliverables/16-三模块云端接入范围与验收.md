# 计划、记账、饮食：云端接入范围与验收

日期：2026-10-21。用户明确要求本轮打通计划、记账、饮食三个模块，替代此前“先交付记账，再扩展计划和饮食”的交付范围。实现可以按依赖分步推进，完成标准必须覆盖三个模块。

## 当前状态

已完成服务器、Docker、MySQL 8.4.11 基础配置，以及应用数据库账号连接、中文和金额读写、事务回滚、服务重启后持久化验收。现有服务器和持久卷继续使用。

以下为用户确认的接入范围和验收约定。后端和 Android 同步现已实现并通过本地模拟器/MySQL 集成验证，实际实现与差异见[文档 17](17-三模块云同步实现映射与验收.md)；云端 API 已启动并通过健康检查，手机联合验收、HTTPS 及异机备份仍待按[文档 18](18-云端部署与手机联调操作.md)执行。依据是 Room v10 schema、现有 Repository 和[本地模块字段清单](12-本地SQL存储与模块字段.md)，早期[接口设计稿](05-接口字段设计.md)仅作为参考。

## 三个模块与关联数据

| 模块 | 已实现的本地表依据 | 本轮云端接入内容 |
|---|---|---|
| 计划 | `plans`、`plan_revisions`、`activities`、`activity_segments`、`activity_tags`，以及 `time_categories`、`projects` | 计划及状态、基线与改期历史、复制/批量生成结果、提醒设置、关联活动、开始/暂停/继续/结束的计时片段、活动分类/项目/标签及现有工作现金字段 |
| 记账 | `ledger_entries` | 收入/支出、来源、金额、发生时间与时区、修改版本、删除标记 |
| 饮食 | `food_versions`、`intakes`、`intake_items` | 食物及历史营养版本、停用状态、三餐与加餐、食用量、摄入明细、营养快照、备注、修改与删除/恢复 |

共同接入账户认证和本机档案绑定。`local_users` 的本机 UUID 不能直接作为云端认证身份；服务端从已验证的登录上下文确定记录归属，同一账户下校验所有关联 ID。

这些表名说明本地数据依据，不表示云端已经建立同名业务表。MySQL 业务结构由版本化迁移创建，另外需要云端账户、幂等操作记录、变更序号及客户端同步状态等结构。

## 需要保留的业务行为

- 计划与改期历史、活动与计时片段及标签，以完整业务操作提交。批量计划重复上传不得重复创建；云端拉取的数据包含提醒设置，手机本地重建提醒调度。
- 活动中的工作现金与独立账本保持现有含义，不能在同步过程中自动相互生成记录，造成重复统计。
- 食物以 `(foodId, version)` 保存历史版本，旧餐食继续使用保存时的营养快照。修改食物营养值后，历史摄入的热量和营养统计保持原有依据。
- 一次摄入及其明细整体提交、整体更新。未知营养、未填食用量等空值保持原意，不填充为零。
- 金额、重量和营养数值继续使用十进制字符串契约，后端按十进制处理。各模块保留原始时间、时区及实际业务枚举。
- 已有睡眠与活动重叠校验也要保留；云端恢复或同步进入本地时，不得跳过与现有本地睡眠记录的关联校验。

## 实现顺序

1. 建立共同后端基础：固定构建与依赖版本、账户与认证、业务迁移、异常处理及部署配置。
2. 实现三个模块的接口和关联校验，覆盖新增、查询、修改、状态变更及各自支持的删除/恢复操作。冻结接口契约及版本规则。
3. Android 接入共同认证、网络客户端、账号绑定、同步队列与同步状态，再把三个模块所有现有写入入口接入队列。上传成功后再更新已确认的服务端版本。
4. 配置 HTTPS，部署到已有服务器；完成三个模块的手机到云端、云端到新测试设备的联合验收。
5. 完成独立备份与隔离恢复。确认真实数据恢复流程后，再作为长期日常存储使用。

## 共同同步要求

- 页面仍先保存 Room，本地业务修改与待同步操作在同一事务提交，断网时三个模块都可继续记录。
- 每次业务操作有稳定 `operationId`，网络超时或重复提交只应用一次；客户端生成 ID，云端按所属账户验证和去重。
- 本地编辑版本与已确认的云端版本分别保存。并发更新有明确冲突结果，不能静默覆盖另一设备记录。
- 增量拉取基于服务端变更顺序和分页游标，删除使用可同步标记，离线旧数据不能复活已删除的记录。
- 初次绑定账号明确确认本地数据导入；导入前保留可恢复备份。恢复另一设备应拉回完整关联与历史快照。
- 所有权与认证在服务端校验。客户端只使用 HTTPS 接口，数据库凭据仅存服务器。

## 完成标准

| 模块 | 手机到云端 | 新测试设备恢复后应成立 |
|---|---|---|
| 计划 | 新建、改期、批量生成、完成/取消；计时的开始/暂停/继续/结束及编辑/删除均正确同步 | 计划状态、改期历史、关联活动、计时片段和分类/项目/标签一致，提醒按本地规则重建 |
| 记账 | 收入与支出新增、编辑、删除均同步，金额精确且重试不重复 | 日期、时区、来源、金额和删除状态一致 |
| 饮食 | 食物新增/版本更新/停用、餐次与加餐的新增/修改/删除/恢复同步 | 食物历史版本与摄入明细完整，既有营养快照及热量结果一致 |

每个模块均需验证离线记录后恢复网络、重复上传、并发版本冲突、删除同步、跨账户访问被拒绝和服务重启后数据保留。备份应恢复到隔离数据库，再核对三个模块的行数、关联及实际接口读取。

只有以上三个模块均通过实际云端验收，才标记“计划、记账、饮食云端存储接入完成”。当前状态为“数据库与 API 已在云端启动并通过健康检查，三模块代码与本地集成验收完成，手机和云端联合验收待执行”。
