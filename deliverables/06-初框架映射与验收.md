## 请求与刷新

- 只有进入“记录”时观察当天摄入；食物列表只在打开摄入编辑器时查询。
- 保存食物后只刷新食物选择列表；旧摄入项持有快照，不重算。
- 保存摄入后 Room 流自动更新当前日期列表及已知热量；不刷新时间洞察或回报。
- 本轮无 HTTP 调用。没有服务端真实返回，界面不绑定未确认字段。

## 反向验收

### 已确认实现

- 四页导航与空数据状态。进入记录页才观察当天 Room 摄入；打开摄入编辑器才查询食物表，无重复 HTTP 请求。
- 新增手工食物时校验名称、非负 kcal、生熟状态和数据来源；保存为营养版本 1。新增一次摄入时显式选餐次，保存食物版本、每 100g kcal 与来源快照；可多次选择加餐。
- 份量为空保留 `null`，计入待补全；完整项用十进制计算并汇总“已知摄入”，展示时才取一位小数。`0` kcal 与未知项区分。
- Debug APK 编译通过；Room schema v1 已生成到 `android/app/schemas/`。

### 与原型存在差异

- 原型的时间线、睡眠、时间条、回报分数和权重表单是示例演示；正式工程当前展示空状态，不搬运示例数值。
- 当前一条摄入只支持一种食物，时间采用保存时刻；原型中更丰富的表单、餐食详情和权重操作尚未移植。底部导航暂用文字标记，未做正式图标及视觉逐像素适配。
- 营养表目前仅支持新增；编辑形成新版本、停用与搜索尚未实现。

### 接口暂不支持 / 字段无法确认

- `05-接口字段设计.md` 的全部 HTTP 路径仍是设计稿，本轮不调用服务端；无 Spring/MySQL 工程或真实返回可确认字段。
- 计划优先级、生理周期事件和权限、备份格式等尚无本地实现，继续标记为待确认。`sourceType`、`mealType` 等采用文档提案枚举，尚未经过后端契约联调。
