# 日有度｜名称、域名与发行签名定案

决定日期：2026-10-22。目标为中国大陆 Android 正式发行：先让受邀者安装签名 APK，再申请应用市场。

| 项目 | 选定值 | 当前状态 |
|---|---|---|
| 应用显示名 | **日有度** | 已在 Android 字符串和需求文档中使用。 |
| 主域名购买目标 | **dayoudu.com** | 尚未购买；2026-10-22 的 `.com` RDAP 查询未发现注册记录，不能代替腾讯云结算页的实时可注册检查。 |
| API 地址 | **api.dayoudu.com** | 子域名无需额外购买；备案通过后再设置 A 记录和 HTTPS。 |
| Android application ID | **com.dayoudu.app** | 已在 `android/app/build.gradle.kts` 中使用；第一份公开发行包前保留不变。 |
| 签名证书别名 | **dayoudu-release** | 只决定别名，密钥和密码尚未生成。 |

不采用 `com.dailyPlanning.app`：当前源码、测试与模拟器数据已经使用 `com.dayoudu.app`，它也与目标域名的反向名称一致。Android [官方建议发布后不要更改 application ID](https://developer.android.com/build/configure-app-module)。如果腾讯云确认 `dayoudu.com` 已被注册、为高价溢价域名或不适合备案，先重新核定域名；**域名选择不影响当前包名或不联网的体验 APK**。显示名可继续保留“日有度”。

选择 `.com` 是为了保留以后在中国大陆以外使用同一品牌的余地，并与现有包名的命名习惯一致；它不是 HTTPS 或中国大陆备案的必选后缀。Android 包名中的 `com` 只是唯一标识的一部分，不要求实际购买 `.com` 域名；只买 `.cn` 时也可以继续使用 `com.dayoudu.app`，但需要把尚未配置的正式 API 地址和文档改成 `.cn`。若 `dayoudu.com` 与 `dayoudu.cn` 都可按普通价格购买，可自愿再买 `.cn` 作品牌保留；当前只配置 `.com` 的 API，`.cn` 不必解析到服务器或额外购置 SSL、DNS 套餐。按[腾讯云当前标准续费价](https://buy.cloud.tencent.com/domain/price?type=renew)，`.com` 约 90 元/年、`.cn` 约 38 元/年；合计约 128 元/年，结算页可能不同。购买两个后缀是可选的品牌费用，不是部署所需。

## 在腾讯云购买域名

1. 使用购买现有上海轻量服务器的腾讯云账号，检查账号实名认证。进入“域名注册 → 信息模板”，创建并等待实名审核通过的信息模板；域名持有人应与你计划使用的备案主体一致。[腾讯云域名实名说明](https://cloud.tencent.com/document/product/242/6707)。
2. 打开[腾讯云域名注册页面](https://buy.cloud.tencent.com/domain)，输入**完整的** `dayoudu.com` 查询。仅当返回“立即加购”且为普通价格时继续；若显示已注册或溢价，停下确认替代名，不购买相似拼写。当前[标准续费价](https://buy.cloud.tencent.com/domain/price?type=renew)约 90 元/年，腾讯云已公告 `.com` [2026-11-01 起调价](https://cloud.tencent.com/announce/detail/2514)；注册和最终费用以结算页为准。
3. 加入购物车，选择已审核的信息模板、购买年限，核对域名每个字母和付款金额后再支付。[腾讯云单域名注册指引](https://cloud.tencent.com/document/product/242/9595)列出查询、购物车、信息模板、核对和付款步骤。首购一年并启用到期提醒/自动续费即可；不选付费证书、付费 DNS 套餐或代办服务。
4. 在“我的域名”确认 `dayoudu.com` 属于自己的账号且实名状态正常。办理腾讯云适用的 ICP/APP 备案；备案和公网前安全步骤见[文档 19](19-域名HTTPS与公网安全上线.md)。备案通过后，才添加 `api` 的 A 记录指向服务器公网 IP，并启动 Caddy HTTPS。

购买域名是付费且一般不能随意改名或退款的操作。不要把腾讯云登录密码、实名证件、付款信息或 App 密码发到聊天；后续协助只需要域名文字和状态（如“已购买、已实名”）。

## 发行签名密钥的创建与保管

Android 使用签名证书判断更新是否来自同一开发者；[不同证书通常不能覆盖升级同一包名的 App](https://developer.android.com/studio/publish/app-signing)。因此第一份给朋友安装的正式 APK 就要用长期密钥，调试密钥不能当发行密钥。

1. 在 Windows 用户目录下创建 `%USERPROFILE%\AppSigning`，把发行密钥放在 `%USERPROFILE%\AppSigning\dayoudu-release.jks`，**不要放入 `C:\code\dailyPlanning`、服务器或公开网盘**。`.gitignore` 已排除常见密钥文件扩展名，但这只是防误提交的辅助措施。
2. 在 Android Studio 选择 **Build → Generate Signed Bundle / APK → APK → Create new**；密钥文件填写上述路径，alias 填 `dayoudu-release`，有效期填 **至少 25 年**。在输入框自己设置独立的高强度随机密码。Android 官方[生成与保管说明](https://developer.android.com/studio/publish/app-signing)建议至少 25 年有效期并妥善保管私钥。
3. 用自己信任的密码管理器保存密钥库密码、密钥密码、alias、包名、生成日期和证书 SHA-256 指纹；**不要**写进 Git、Gradle 文件、聊天、截图或服务器 `.env`。可让两个密码不同，但要分别保存并验证；不要与 App 登录/SSH/MySQL 密码复用。
4. 保存两份 `dayoudu-release.jks` 副本：电脑原件 + 一个加密的离线 U 盘或其他独立加密存储。密码管理器与密钥文件不要只依赖同一台电脑或同一账号。备份后校验能以别名和密码读取证书；每次更换电脑先验证备份可用，再删除旧设备中的副本。
5. 初次签名后记录 APK 的证书指纹，后续每版复查包名、证书指纹和递增的 `versionCode`。如果以后进入 Google Play，要在首次入驻时确认 Play App Signing 的密钥策略；若希望商店安装版可覆盖朋友收到的 APK，须保持实际安装到设备的**应用签名证书**一致，而不仅是上传密钥一致。

尚未购买域名，也未生成发行密钥或朋友用的正式签名 APK。不联网的少量熟人体验 APK 可先使用 Debug 构建，但必须说明云端账户不可用、数据仅在手机上、后续正式签名包通常不能覆盖 Debug 安装。持续分发的正式离线包需先完成发行签名与真机验收；接入公网云服务的版本还需完成备案、HTTPS、安全、隐私和备份验收。
