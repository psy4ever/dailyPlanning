# 日有度｜界面视觉改版映射

> 此文记录 2026-10-20 第一轮视觉实现；“今天”页的焦点卡和计划操作已在随后一轮按用户反馈调整，现行交互以 [09-每日计划交互与文档格式映射.md](09-每日计划交互与文档格式映射.md) 为准。

日期：2026-10-20。依据用户提供的三屏原型图与 `宪法.txt`，本轮只调整 Android Compose 的四个页面、底部导航与必要的矢量图标，不改 Room、业务算法或 HTTP 契约。原型中的日期、餐食、热量、评分、金额均为示例，界面只绑定现有本地数据；空数据保留简短引导。

| 原型元素 | 用户操作 | 业务状态 | 所需数据 | 本地接口／规划 HTTP | 参数 → 返回字段 | Compose 变量 | 当前代码位置 | 已确认 |
|---|---|---|---|---|---|---|---|---|
| 底部四栏图标与暖白背景 | 切换页面 | 当前 Tab | 当前 Tab 枚举 | 本地导航／无 HTTP | Tab → 页面 | `selectedTab` | `MainActivity.kt` | 四栏已确认；颜色与图标为视觉实现 |

| 今天松绿焦点卡 | 开始/暂停/继续当前活动或开始下一计划 | 计时/计划状态 | `active`, 当日未来计划 | 现有 `PlanningRepository` | `planId/category` → 会话状态 | `active`, `focusPlan` | `TodayScreen.kt` | 仅真实计划或活动可显示标题 |

视觉实现使用现有 Material3 `Surface`、渐变和页面内排版，不新增公共 UI 包装层；底部图标新增四个可复用的 repo 原生 VectorDrawable。替代方案是在四栏使用文字字符图标，但清晰度不及矢量图。食物弹窗、计时/备份业务接口与数据库不在本次范围。

## 反向验收（2026-10-20）

| 代码/界面 | 映射原型 | 结果与差异 |
|---|---|---|
| `MainActivity.kt` 与四个 `tab_*.xml` | 暖白底色、松绿主色、图标底栏 | 已实现；图标为本地矢量，未增加图片加载或网络请求 |
| `TodayScreen.kt` | 周日期条、深绿焦点卡、时间线 | 已实现；焦点只显示真实计时或未来计划，空数据时提供新建计划；计划操作分两行以适应窄屏 |
| `RecordScreen.kt` | 摄入摘要、餐食卡、其他记录 | 已实现；只显示已知 kcal 和待补项，不显示原型示例目标；睡眠仍按醒来日读取 |
| `InsightsScreen.kt` | 分段时间条、图例、个人回报 | 已实现；分段来自实际时间统计，模型和评价仅在展开后读取；无工作现金时不显示空占位 |
| `MineScreen.kt` | 统一卡片与简短设置项 | 已实现；保留备份文件包含个人数据的必要提示 |

已移除“按自己的标准，看回报”“饮水及其他可选模块将在后续阶段接入”等说明文字；全局搜索未发现“预留”或原型示例数据被写入 UI。`assembleDebug` 构建成功；模拟器中实际查看了四页的空数据布局，并在重连后截图确认状态栏图标与浅背景的对比度。原型中的食物插画和样例餐次没有对应真实数据，使用现有矢量图标、渐变和色块表达视觉层次；未向用户生成虚构记录。
